# 设备约束下的实验方案

## 本机与测量边界

2026-10-04 实读硬件：MacBook Air / Mac16,12，Apple M4，10 核 CPU（4 性能 + 6 能效）、8 核 GPU、16 GiB 统一内存。磁盘是动态快照：早期 `df -h` 显示约 12 GiB 可用；最终 MPS 进程 `shutil.disk_usage` 记录约 37.83 GiB。二者时点与系统可回收空间口径可能不同，不能当作持续保证；每次训练前应重新测量并取保守预算。本次未测交换量、温度或长时间降频。

系统默认 Python 3.14.7；复用已有 Python 3.10.18 环境完成 PyTorch 2.14.0 / tokenizers 0.22.1 运行，无模型或大数据下载。受限进程最初报告 MPS 不可用，正常本机权限下确认可用并实际训练；这不能被解释为 M4 不支持 MPS。

主线是 PyTorch CPU/MPS，接口保留 CUDA。MLX LM 的现成模型 LoRA/量化支线与随机初始化训练分开报告；当前未实现该支线。

## 资源账本

| 配置 | 实际架构目标 P | FP32 权重/梯度/Adam 两状态（16P） | 冻结 DPO 参考额外（4P） |
|---|---:|---:|---:|
| 30M | 29,676,544 | 0.442 GiB | 0.111 GiB |
| 100M | 91,740,672 | 1.367 GiB | 0.342 GiB |
| 0.5B | 514,859,520 | 7.672 GiB | 1.918 GiB |

还必须预留激活、注意力临时张量、框架、数据、系统和保存检查点时的 CPU 副本。当前检查点序列化会额外复制状态，**约 0.5B 在 16 GiB 上尤其不能由 7.672 GiB 状态估算推导可行**。完整预训练检查点约 12P bytes；DPO 含参考约 16P。保存期间还要保留旧文件和临时文件。模型推理能装下、LoRA能运行都不能证明全参数训练可行。

首轮 30M 建议先固定较小许可语料、真实 8K BPE、context 128–256、microbatch 1，测 100–200 次更新；再进行至少 10–20 分钟相同配置持续测量，并记录交换量与内存压力。当前文件默认 context 512，可复制新配置显式改小，不能只改描述。正式 token 预算应在测量后填写。

进入 100M/0.5B 前分别完成：

1. 确认上一个档位的预训练、恢复、SFT、DPO、同一评测集和新进程推理都能复现。
2. 单独记录预训练、SFT 和 DPO 的稳定吞吐、内存压力、保存峰值、检查点磁盘占用；DPO额外参考计算不能忽略。
3. 给系统和其它应用留出充足空间，无持续交换或明显降频，磁盘至少容纳保留策略及原子保存副本。
4. 按 `计划处理token / 同配置持续tokens每秒` 估计净训练时间，另加评测/保存/中断；不能代入 tiny 结果或外部 GPU 宣传时间。
5. 若本机不满足资源预算，保持 30M/100M，或先做保存内存优化/租用明确预算设备。约 0.5B 是条件候选，没有承诺本机一定执行。

## 数据和实验顺序

T0 已完成可迁移项目和预算工具；T1–T6 已在 tiny 合成 fixture 层面形成最小工程闭环。下一阶段是实际语料与 30M 资源实验，不应将 tiny 成果写成 30M 已训练。

- 数据：优先范围明确、自有或有清楚训练许可的少量语料。记录来源 URL/版本、取得时间、许可、文件哈希；先按文档/来源组划分，再只用 train 拟合 BPE。加入近重复检测和外部评测污染检查后才能使用正式评测。
- 分词：8K byte-level BPE 为主线候选，记录实际词表；固定它后比较架构。纯字符合并教学演示与实际 byte-level 实现分开。
- 预训练：随机初始化 GPT decoder，以 next-token loss 检验训练。每轮只改可归因变量；记录处理 token（含重复）与独立语料 token，不能混称。
- SFT：人工复核的 prompt/answer，只有 assistant completion 与 EOS 计 loss。各阶段共同维护持出问题清单。
- DPO：相同 prompt 的 chosen/rejected，冻结 SFT 参考。以原论文的序列 log probability 求和，观察长度偏置、拒答和退化；不因 DPO loss下降就宣布能力改善。
- 评测：同一保留集、tokenizer、提示模板、解码与模型选择规则；报告逐题结果、NLL/PPL、completion 指标与限制。重复查看 test 的 tiny fixture 只用于工程调试，不能充当一次性正式 test。
- 部署：首先是当前可运行的 greedy CLI，新进程载入全部产物；量化/格式转换/网络API作为单独验证的扩展。

旧 1B 计划不再作为默认执行目标。下一档 30M、后续约100M和约0.5B分别受测量条件约束。公开项目发布优先代码、数据卡、模型卡和真实报告；权重和大型语料在许可及资源核查后单独发布。
