前三篇讲了历史、腿的几何和用遗传算法重新演化它。这一篇讲我把这些东西拼成了什么：一个开源平台，思路是一个闭环：

**设计 → 仿真 → 3D 打印 → 测量 → 校准 → 再设计**

代码在 [meiluosi/strandbeest-evolution](https://github.com/meiluosi/strandbeest-evolution)，MIT 许可。受众是开发者、相关专业人员和爱好者。后端没有登录也不公开托管，在本机或用 `docker compose` 跑；另外有一个公开的**静态**演示（不需要后端，打开就能拖连杆、跑浏览器里的仿真）：[在线演示](https://meiluosi.github.io/strandbeest-evolution/)。

## 各部分是什么

- **设计器**（浏览器里）：拖动 13 个连杆长度看脚轨迹，铰点标字母，还能让遗传算法在浏览器里替你演化。
- **制造**：从一份设计文件生成可打印的零件：杆、曲柄臂（轴端是紧配孔、销端是松孔）、相位夹具、隔套、撑杆、电机座、联轴器的 STL，加上物料清单、装配说明和可打印性检查。杆件按"共用销轴或会互相扫到"分层，我用比规划更细的角度步长验证过，同层的杆在整个曲柄周期里都不会相撞。网页里能看到会动的 3D 装配预览，也能看单个零件的 STL。
- **仿真**：MuJoCo 搭的平面多体仿真器，场景用一个配置文件描述。支持参数扫描、任务队列（重启后任务不丢）、结果按运行保存、可复现。旁边还有一个**独立**求解器 K2（平面刚体、真正的库仑干摩擦，不共享 MuJoCo 的接触代码）：两者在慢速平地行走上每圈步幅差 0.58 %，起步风速差 4.4 %，这是 E1（两个独立求解器一致）。
- **实验室**：导入测试台的原始数据，转成带质量报告的测量，叠在仿真上看，再让校准去拟合足垫刚度和摩擦。
- **测试台**（`hardware/`）：测试台方案、标定流程、五个实验（E0 到 E4）、ESP32 固件、实验笔记模板；ArUco 视频追踪的代码在 `packages/rig`。
- **社区数据入口**（`docs/HOW-TO-MEASURE.md`）：中英双语的《如何测一只走兽》指南、Measurement 提交格式和一个校验器，陌生人按文档走一遍就能交上一份通过校验的数据。

## 说清楚哪些是真的

- **没有一样东西接触过真实硬件。** 固件的逻辑核心在本机做了单元测试，Arduino 外壳没编译过；零件建议只写了类别，没核实具体型号；导出的零件（电机孔距、联轴器、压配偏置）含假设，第一次打印一定要调。
- **校准只在合成数据上核对过。** 它证明了"导入、对照、拟合"这条链路本身没错，不证明真实数据也能拟合出有物理意义的值。更进一步的结论是：在合成数据上，**接触刚度和摩擦都不可辨识**——后验区间宽到覆盖先验的大部分，点估计不能用，能用的是区间本身。
- **扭矩水平依赖摩擦的数值处理**（见上一篇），所以界面报告范围而不是单个数。
- 简化模型的起步风速和峰值扭矩**没有得到验证**。现在模型给出的起步风速是 0.489 m/s（区间 0.479–0.500；判据是静止起步后 40 秒内转满一圈），但这个数最怕的不是模型错，而是**销轴摩擦**：只要每个关节有 0.5 mN·m 的摩擦，所需风速就升到 1.02–1.07 m/s（+110 %–+160 %）。销轴摩擦是这里最大的未知量，只能靠实测。

## 试试看

```bash
./scripts/setup-python.sh && source .venv/bin/activate
strandbeest-api                                   # 后端
pnpm install && pnpm --filter @strandbeest/web-demo dev   # 网页
# 或者一键：docker compose up --build
```

欢迎 issue 和 PR，尤其欢迎真实测量数据，那是目前最缺的东西。仓库里有一份写好的《如何测一只走兽》指南（`docs/HOW-TO-MEASURE.md`，中英双语），照着它交一份数据就能通过校验——现在缺的已经不是通道，是数据。
