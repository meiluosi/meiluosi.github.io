“中文 70%，英文 30%”看似是一份清楚的训练配方，但它可能表示文件大小、文档数量、抽样概率或 token 数。只要中英文文档的平均长度不同，这几种配方就不会产生相同训练。

在清洗、质量筛选和去重之后，仍需要把语料池转换成有限的训练预算。混合数据的核心是分配暴露机会：哪些内容出现，出现多少次，在什么训练阶段出现，又有多少位置真正参与损失计算。

本文是第一卷第五篇。前一篇讨论[去重与评测污染](/posts/2026-10-15-llm-training-data-04-dedup/)，下一篇将这些决策组织为[可追溯的构建流程](/posts/2026-10-15-llm-training-data-06-build/)。

## 一、语料库存与训练分布是两个对象

设有 $K$ 个数据域，每个域形成一个样本分布 $p_i(x)$，训练时先以概率 $\alpha_i$ 选择数据域，再从域内取样，则混合分布为：

$$
p_\alpha(x)=\sum_{i=1}^{K}\alpha_i p_i(x),
\qquad \alpha_i\ge0,\quad \sum_i\alpha_i=1.
$$

对应的期望目标可写成：

$$
\mathcal{L}(\theta;\alpha)=
\sum_i\alpha_i\mathbb{E}_{x\sim p_i}[\ell_\theta(x)].
$$

这个表达式还没有完全定义训练。$x$ 是整篇文档、固定长度块还是单个预测位置？$\ell$ 按样本平均还是按有效 token 平均？这些选择会决定同一个 $\alpha$ 的含义。

因此，配方应该写成“以有效训练 token 为目标，中文技术、中文通用、英文通用分别占多少”，或者明确写成“按固定长度块采样”。单独写一个百分比表并不足够。

## 二、文档采样概率怎样换算成 token 占比

假设先按概率 $\alpha_i$ 选择域，然后均匀选择一篇文档，完整消费文档。设域 $i$ 的平均 token 长度为 $\mu_i$。经过足够多次采样，域 $i$ 的预期 token 占比近似为：

$$
\beta_i=\frac{\alpha_i\mu_i}{\sum_j\alpha_j\mu_j}.
$$

这是在平均长度稳定、不截断、不丢弃且所有位置同等计入的假设下得到的关系。它指出长文档域会贡献更多 token。

一个自拟算例：中文与英文文档都以 50% 概率抽取，平均长度分别为 1,000 与 2,000 tokens。实际 token 占比约为中文 $1/3$、英文 $2/3$，不是各一半。

若目标 token 占比为 $\beta_i$，可反推文档抽样权重：

$$
\alpha_i=
\frac{\beta_i/\mu_i}{\sum_j\beta_j/\mu_j}.
$$

继续使用上述长度，若希望中英文 token 各占 50%，中文文档应以约 $2/3$ 的概率抽取，英文约 $1/3$。如果后来过滤使中文平均长度发生变化，就需要重新估计，而不是继续使用旧权重。

实际训练常按固定长度块混合，这可以简化比例控制，但尾块、padding、跨文档边界和 loss mask 仍会产生差异。最终应从训练日志回算每个来源的有效 token，而不仅检查配置文件。

## 三、tokenizer 也参与分配预算

同一句话在不同 tokenizer 下可能被拆成不同数量的 token。中英文在同一 tokenizer 下的切分效率也可能不同。因此，token 预算不是独立于 tokenizer 的自然单位。

至少需要记录词表、规范化方式、特殊 token 配置以及版本。对于新训练的 tokenizer，应先划分数据集合，只使用训练部分拟合；对于已有 tokenizer，则记录其来源和已知训练背景，不应声称自己重新建立了完整的数据隔离。

可以在固定样本上统计每字符 token 数、每字节 token 数与文档长度分布，观察切分效率。它们描述编码成本，不直接等于语义质量。某个 tokenizer 产生更少 token，可能降低处理长度，也可能改变词表开销和泛化行为。

跨 tokenizer 比较困惑度时尤其要谨慎。每 token 的负对数似然受切分粒度影响。按字符或字节归一化可以提供另一种视角，但编码表示、规范化和文档边界仍需统一，不能用一个归一化公式消除所有比较差异。

## 四、自然比例、均匀比例与温度采样

最直接的混合方式是按去重后 token 库存量采样。设库存为 $n_i$，取 $\alpha_i=n_i/\sum_jn_j$。这可以较充分利用大来源，但库存大的领域可能主导训练。

另一极端是每个来源等概率。它保证每个来源都有机会，却可能反复抽取小语料。折中形式之一是幂次平滑：

$$
\alpha_i=\frac{n_i^\gamma}{\sum_jn_j^\gamma},
\qquad 0\le\gamma\le1.
$$

$\gamma=1$ 保留库存比例，$\gamma=0$ 对非空来源均匀分配，介于两者之间会提高小来源的相对份额。有些资料用温度 $T$，写成指数 $1/T$，因此记录公式比只记录“temperature=2”更清楚。

假设两份等口径的库存比例为 90:10，取 $\gamma=0.5$，权重成为 $\sqrt{90}:\sqrt{10}=3:1$，即 75:25。较小来源从 10% 提高到 25%，但其中的独立内容并没有增加。

以上是采样设计的数学例子，不是推荐中英文使用某个固定比例。中文技术模型、英文通用模型与双语检索模型需要的分布可能不同，模型容量和 tokenizer 也会影响结果。

## 五、重复暴露是预算的一部分

设总训练预算为 $B$ 个有效 token，域 $i$ 的目标 token 占比为 $\beta_i$，去重后可用库存为 $n_i$，则可以定义一个近似的等效遍历次数：

$$
e_i\approx\frac{B\beta_i}{n_i}.
$$

这个指标方便发现小语料过度使用，但它是平均暴露量，不保证每个文档都恰好出现 $e_i$ 次。权重不均、变长文档和有放回采样都会导致不同样本出现次数不同。

| 教学设定 | 数值 |
| --- | --- |
| 总有效训练预算 | 1B tokens |
| 中文技术域占比 | 40% |
| 中文技术域独立库存 | 100M tokens |
| 等效遍历次数 | $1\mathrm{B}\times0.4/100\mathrm{M}=4$ |

如果库存因质量过滤减少一半，而预算与配比不变，等效遍历就变成八次。于是“提高质量阈值”与“提高重复暴露”会同时发生，训练实验需要把它们一起记录。

在更简单的等长块、有放回均匀采样情形下，从 $N$ 个块抽取 $m$ 次，期望见到的不同块数为：

$$
N\left[1-\left(1-\frac{1}{N}\right)^m\right].
$$

因为任意一个块始终未被抽中的概率是 $(1-1/N)^m$。当 $m=N$ 且 $N$ 很大时，覆盖率约为 $1-e^{-1}\approx63.2\%$。因此，“抽取了相当于一遍库存的 token”不一定等于“每条数据都看过一遍”。

逐轮无放回遍历则有不同覆盖性质。数据加载器是否循环、何时重洗牌、如何处理耗尽来源，必须成为配方的一部分。

## 六、语言、领域和文体最好分别建模

中文网页与英文代码不是两个对称的语言域：它们同时在语言和内容类型上不同。若把训练效果变化全部归因于中英文比例，就会混淆语言与领域的作用。

可以按层次记录：语言、领域、文体、质量分段、自然或合成、长度区间。具体采样未必需要实现所有组合，但日志应尽可能保留这些标签，以便解释结果。

例如先固定代码比例，再比较中文通用与英文通用的变化，可以减少一个混杂因素；先固定语言比例，再比较中文技术与中文通用，则回答领域适配问题。两种设计都合理，但问题不同。

中英混排记录也需要明确口径。可以将整篇归到独立混排域，也可以按段落统计；如果只使用文档主语言标签，日志中的“中文 token”其实是“被标为中文的文档所贡献的 token”，不等于逐 token 语言识别。

## 七、数据混合可以从训练反馈中学习

手工混合的局限是候选组合很多，而完整训练昂贵。DoReMi 提出用较小的参考模型和代理模型寻找域权重，再将得到的平均权重用于更大模型训练。它使用相对参考模型的超额损失，而不只关注哪个域的原始损失最高。[DoReMi 论文 §2](https://arxiv.org/html/2305.10429v3#S2)

直觉上，原始损失高可能表示噪声多，而不一定表示值得投入更多预算。参考模型提供一个比较基准，让方法关注代理模型相对基准尚未学好的部分。完整算法还涉及权重更新、平滑与具体损失处理，不能将“按 loss 排序”称为复现 DoReMi。

对个人研究而言，首先可以学习其比较思路：分别观察各域损失，设置共同参考，不只优化一个总体平均数。是否值得训练额外代理模型，要把代理阶段成本计入总预算。

权重迁移也有边界。小模型与大模型的能力、训练时长和表示效率不同，一组权重在代理模型上有效，不保证在任意规模都最优。改变领域划分、tokenizer 或主要训练算法，都可能需要重新比较。

## 八、分阶段混合要记录整个轨迹

训练可以先覆盖广泛内容，再提高目标领域比例；也可以在继续预训练阶段引入新内容。这样的设计会同时改变数据分布与训练时间位置。

因此，除了最后的比例，还要记录每个阶段的 token 预算、学习率、数据版本以及阶段边界。可以用 $\beta_i(t)$ 表示随训练进度变化的 token 权重，实际累计暴露量近似为对训练位置的积分或逐步求和。

比较静态与动态配方时，如果动态方案最后增加了额外训练 token，观察到的收益不能全部归因于课程顺序。若要研究顺序，应尽量保持各域累计 token 相同，只改变呈现时间；若要研究完整方案的实用效果，则可以保留不同预算，但必须报告成本。

对继续预训练，还需要追踪原有能力是否退化。目标领域验证损失下降，同时通用语言能力下降，是一种需要取舍的结果，不能只报告前者。

## 九、打包和 loss mask 会让配方再次变化

将短文档拼成固定长度序列可以减少 padding，但需要说明文档边界如何处理。插入 EOS 只增加了边界符号，并不会自动阻止后一个文档注意到前一个文档；若需要真正隔离，还涉及注意力掩码与位置处理。

跨文档预测、尾块丢弃和 padding mask 都影响有效训练位置。例如两个来源的输入 token 各占一半，但其中一个来源大量位置被 mask，最终梯度贡献就不再是一半。

损失归一化也会产生影响。先对每条变长序列取平均、再对序列平均，相当于给每条序列相近权重；将全部有效 token 的损失求和再除以总有效 token，则给每个预测位置相近权重。它们在长度不同时不等价。

所以日志建议区分读取 token、送入模型 token、有效预测 token 和被重复采样的 token。显存吞吐可以用输入 token 表示，训练配方则更需要知道真正参与优化的部分。

## 十、怎样设计一组可解释的混合实验

先声明问题。若研究“固定预算下哪种中英文比例更好”，可以从同一去重池构造少量比例，固定模型、tokenizer、有效 token 总数、学习率日程和上下文设置。质量分布、领域比例与重复暴露应尽量控制，不能控制的部分作为伴随变化报告。

评测需要覆盖中文、英文和目标领域，而不是只看一个平均分。语言模型验证损失适合追踪学习过程，知识题、技术任务和生成检查分别反映其他能力。小模型若在某项任务上接近随机猜测，微小分数波动可能没有足够区分力。

要比较训练效率，可以补充两种视角：固定有效 token 的效果，固定计算或墙钟预算的效果。不同序列长度与 tokenizer 可能改变成本，两个视角不一定得到同一排名。

还应预先决定如何选模型和阈值。反复查看最终测试集并调整比例，会把测试集变成开发集；保留独立最终评测，才有机会判断所选配方是否能泛化。

| 关键判断 | 证据性质 | 条件 |
| --- | --- | --- |
| 文档权重与 token 权重通常不同 | 平均长度下的推导 | 完整消费且长度分布稳定 |
| 上采样提高暴露量而非独立库存 | 预算定义与覆盖率推导 | 实际覆盖取决于采样方式 |
| 小模型可以用于学习域权重 | DoReMi 的方法与实验 | 迁移效果受模型与配方限制 |
| 分阶段训练适合当前中文任务 | 待验证的设计 | 同时评估目标收益与通用能力变化 |

可以检查两个问题：如果中文文档平均更短，文档各抽一半为什么不能保证中文 token 占一半？如果提高质量阈值后效果下降，你会怎样判断是多样性减少，还是小语料被重复使用得更多？
